# 모멘텀 맵 페이지

기존 Investing Desk의 사이드 메뉴에 `모멘텀 맵`을 추가한다. 주소는 `/investing/#/momentum`이다. GitHub Pages가 경로를 서버 라우팅하지 않아도 새로고침과 공유 링크가 동작하도록 hash 경로를 사용한다. 기존 첫 화면은 Hyperscaler로 유지한다.

## 제공 화면

- 글로벌 자산군: Binance BTC·ETH USDT 프로필과 Coinbase BTC·ETH USD 프로필. 날짜별 13개 고정 모집단을 각각 조회한다. 서로 다른 거래소의 시계열을 합치지 않는다.
- 미국 ETF: 31개 좌표와 26개 주식 ETF 관측 순위. SPY·참고 자산은 순위 모집단에서 제외하며 유동성 상태는 별도 표시한다.
- 관측일 선택 및 이전/다음 버튼, 최신 관측일 이동, 자산 검색·선택·상세 수치, 80/95/99% 역사적 경계 토글, 전체 자산 표와 출처·산식 설명.
- 모든 프로필은 전체 순위 최신일을 기본으로 연다. 경계가 보류되어도 최신 순위를 표시한다. 요청한 날짜가 없으면 기본일을 표시하고 이유를 알린다.
- 순위가 보류된 날짜는 부분 순위를 새로 계산하지 않는다. 좌표가 유효한 자산만 그리며 빠진 자산과 사유를 표시한다. 선택한 날짜의 경계가 없으면 이전 경계를 가져오지 않는다.
- 버블 면적은 미국의 평균 거래대금 또는 글로벌의 연율 변동성에 비례한다. 날짜별 최댓값으로 크기를 정규화하고 최소 표시 반경을 적용하므로 날짜 간 면적을 절대 규모로 비교하면 안 된다. 미국 유동성 미확인·미달은 ×이며 상세에서 구분한다.
- 축 범위는 날짜의 좌표와 경계로 정한다. 같은 날짜에서 경계 표시 토글·검색·자산 선택은 축 범위를 바꾸지 않는다. 작은 화면에서는 상위 5개와 선택한 자산의 라벨을 우선 표시한다. 모든 값은 표로 접근할 수 있다.

공유 예: `#/momentum?profile=global_binance&date=2026-09-11`. 프로필 키는 `us_etf`, `global_binance`, `global_coinbase`다.

## 데이터 연결

브라우저는 PostgreSQL에 직접 연결하지 않는다. `scripts/export_momentum.py`가 전용 DB `asset_momentum`을 **read-only/repeatable-read**로 읽고 공개 필드를 명시적으로 선택한다. 원문 응답·개인정보·DSN·임의의 DB JSON metadata는 출력하지 않는다. 입력 실행 ID를 명시적으로 선택하며 최신 실행을 자동 추측하지 않는다. 실제 내보낸 파일은 `public/momentum/`에 있다.

```sh
# psycopg가 있는 기존 파이프라인 Python 환경에서 실행
PYTHONDONTWRITEBYTECODE=1 /Users/pkh876/project1/.venv/bin/python scripts/export_momentum.py
```

필요하면 `ASSET_MOMENTUM_POSTGRES_DSN`을 환경으로 지정한다. DB명은 `asset_momentum`만 허용하며 저장소·명령 인자·출력 JSON에 인증 정보를 남기지 않는다. 실행 ID를 갱신할 때는 다음 인자를 사용한다.

```sh
python scripts/export_momentum.py \
  --us-etf-run <coordinate-run-id> \
  --global-binance-run <global-run-id> \
  --global-coinbase-run <global-run-id>
```

미국 경계는 선택한 좌표 실행과 동일한 `coordinate_run_id`의 날짜별 완료 실행만 연결한다. 글로벌 경계는 좌표와 동일한 실행에서 읽는다. 모든 날짜의 모집단·순위 보류·경계 3종·현재일 제외를 검증한 후 출력한다. 숫자는 표시용으로 소수 8자리까지 보존한다. 점수·순위를 프론트엔드에서 재산출하지 않는다.

파일명에 SHA-256 앞 12자리를 넣고 manifest는 마지막에 교체한다. 브라우저가 manifest의 전체 SHA-256을 검증한 뒤 파일을 표시한다. 페이지·프로필을 필요할 때만 로딩한다. 데이터 갱신 시 사용하지 않는 이전 프로필 JSON만 정리한다.

## 검증과 게시

`npm test`는 기존 테스트와 새 스냅샷 검증을 실행한다. `npm run build`는 TypeScript와 Vite 정적 빌드를 실행한다. UI는 날짜·프로필·검색·자산 선택·키보드·경계 토글·보류 상태·모바일 폭·기존 메뉴·새로고침을 브라우저에서 확인한다.

GitHub의 기존 `Deploy Pages` workflow가 main 변경을 빌드·게시한다. 이 기능은 새 DB 연결이나 API 키를 GitHub에 요구하지 않는다. 정기 데이터 갱신 스케줄은 이번 작업에서 만들지 않는다. 새 원천 계산을 마친 뒤 로컬 exporter로 JSON을 갱신하고 `npm test`와 `npm run build`를 거쳐 데이터 변경을 커밋한다.

연준 최신값 유지 변경은 `codex/momentum-fed-carry-20260913` 브랜치에서 진행한다. 코드·테스트, 데이터, 문서를 별도 커밋으로 관리하며 실제 게시 여부는 PR 병합·Pages 실행 결과로 확인한다. 임시 점검 산출물과 단계별 DB 백업을 추가 보관하지 않는다.

## 이번 검증 결과

- 최초 게시 검증: 테스트 50개 통과. 모든 스냅샷의 날짜·모집단·순위·결측·경계 상태·SHA-256을 검사하고 잘못된 패널을 거부하는 사례를 확인했다.
- DB와 별도 대조: 좌표 22,769개 × X/Y/점수/순위/크기 = 113,845개 표시 값이 소수 8자리 기준 모두 일치했다.
- 375px·768px·1440px에서 페이지 가로 넘침이 없었다. 검색·빈 검색·점 선택·Enter 키·경계 토글 시 축 고정·이전/다음 날짜·거래소 선택·기존 메뉴·뒤로가기를 확인했다.
- GitHub Pages와 같은 `/investing/` 하위 경로에서 정적 빌드의 직접 링크와 새로고침을 확인했다. 브라우저 오류·경고 로그는 없었다.
- Vite는 기존 메인 번들의 500kB 초과 안내를 출력한다. 모멘텀 페이지는 별도 지연 로딩 번들이다. 기존 차트 라이브러리의 메인 번들 분할은 이번 범위에 포함하지 않는다.

## 연준 최신값 유지 정책 검증

공개 글로벌 좌표에는 `source_date`, `source_age_days`, `carried`를 추가했다. 두 연준 계열만 이전 관측일을 허용하고 미래 날짜·잘못된 경과 일수·허위 유지 표시를 exporter에서 거부한다. DB 산출은 `--fed-latest-available` 정책으로 실행하며, 기본 exporter가 사용하는 새 실행은 Binance `a9da8669-7e99-4fe6-a71c-52c682fd0574`, Coinbase `c4df5169-7846-4cd4-97dc-cdae4b82eff4`다. 기존 동시 관측일 실행은 DB에 보존한다.
